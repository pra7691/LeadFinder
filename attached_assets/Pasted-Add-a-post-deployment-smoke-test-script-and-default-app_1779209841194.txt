Add a post-deployment smoke test script and default app settings seed.

Do not rebuild the app.
Do not change unrelated modules.

Goal:
Make production deployment safer by verifying that the API, database, schema, and critical settings are ready before actual usage.

PART 1 — POST-DEPLOYMENT SMOKE TEST SCRIPT

Create a script:

scripts/smoke-test-production.ts

or similar.

The script should accept:

API_BASE_URL

Example:
API_BASE_URL=https://yourdomain.com pnpm run smoke:test

The script should check:

1. GET /api/healthz
Expected:
status 200
{ "status": "ok" }

2. GET /api/healthz/deep
Expected:
status is "ok" or "warning"

Fail the script if:
- API is unreachable
- database is not connected
- required tables are missing
- required columns are missing
- status = error

Allow warning if:
- optional app settings are missing

But clearly print warnings.

Output should be readable:

API Health: OK
Database: Connected
Schema: OK
Warnings:
- blocked_domains not configured
- ai_enabled not configured

Exit codes:
- 0 = safe to continue
- 1 = deployment is broken

PART 2 — PACKAGE SCRIPT

Add package.json command:

pnpm run smoke:test

or workspace-compatible equivalent.

Document exact usage.
