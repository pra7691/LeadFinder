Fix and unify AI usage across the application.

Current AI audit findings:

1. There are two separate AI systems:

   * Replit OpenAI integration proxy used by lead relevance scoring.
   * User-configured OpenAI API key from Settings used by email personalization.

2. Lead relevance scoring is not actually using AI because scorer.ts uses an invalid/hardcoded model and silently falls back to keyword scoring.

3. Email personalization correctly uses the OpenAI key saved in Settings.

Goal:
Use one consistent AI system across the app:
Settings → OpenAI API Key + Model → all AI features.

Do not add new AI features.
Do not change unrelated modules.
Fix the current AI architecture.

=================================================

Update relevance scoring so it does NOT depend on:
AI_INTEGRATIONS_OPENAI_API_KEY
AI_INTEGRATIONS_OPENAI_BASE_URL
@workspace/integrations-openai-ai-server

Scoring should use the same OpenAI API key and model saved in app_settings.

Settings should control:

* email personalization
* AI regeneration
* relevance scoring

==================================================
PART 2 — FIX MODEL HANDLING
===========================

Do not hardcode invalid model names.

Use:

* openai_model from app_settings
* fallback model from app config if missing

Default fallback:
gpt-4o-mini

The model selector in Settings must affect:

* email personalization
* regenerate with AI
* relevance scoring

==================================================
PART 3 — GRACEFUL FALLBACK
==========================

If AI is disabled, missing, or fails:

* do not crash server
* use keyword/rule-based fallback scoring
* clearly record that fallback was used

Add fields or logs where practical:

* ai_used: true/false
* scoring_method: ai / keyword_fallback
* ai_error_message if failed
